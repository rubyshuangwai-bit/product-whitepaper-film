# 更新、同步与开源候选包

此参考仅用于维护/分享这个Skill，不要求每次制作产品视频都准备开源发布。

## 先把 Skill 更新到一致版本

修改SKILL.md、实际脚本/示例及其说明，版本写在入口metadata与README。核对真实实现，不只改介绍文字。保留已确认行为和旧版本；同步本地安装副本时移除已被替换的旧文件，防止旧脚本仍被调用。对比关键文件hash，确保编辑目录、安装目录与压缩包内容一致。

仅改文案和入口时，检查结构、引用和版本即可；变更代码时测试受影响功能；改变动画/配音时重新验证受影响的画面/音轨，不无理由重复整套测试。

## 发布说明要能对应证据

- README说明：用途、输入、输出、最短可运行方式、依赖，以及当前示例。
- 展示材料：用可公开的虚构资料或已获许可的材料。提供视频预览或GIF时确认音色与素材使用范围；本机个人默认音色不自动成为公开演示素材。
- 许可：准确记录实际依赖，保留需要随包分发的版权与许可信息。
- 验证：区分结构/布局/解码、语音识别、实际试听、用户观感、跨机器兼容。未做的检查写待验证，不将“无报错”扩写为全面质量通过。

公开包只放通用方法和人工编排的虚构示例，不纳入用户案例、测试过程、个人配置或验收记录。

## 生成可分享的包

```bash
python3 scripts/package.py --out /absolute/path/product-whitepaper-film-0.4.8.zip
```

从当前整个Skill目录生成候选包；输出已存在则停止。打包器限制文件类型并检查常见个人路径/密钥模式，排除运行配置、音视频、模型和生成目录。显式公开文件清单、邮箱/手机号/常见凭据扫描和固定归档时间不能替代逐文件人工核查；仍需查看归档清单。保留随包的LICENSE、THIRD_PARTY_NOTICES和来源说明。

检查压缩包能解压、相对文档链接存在，并在允许的本机环境运行示例。只报告当前实际完成的检查，不冒称跨机测试。

## 再准备仓库与发布

Skill源码先完成并同步，再整理仓库首页、效果演示和适用边界。外部上传时核对目标仓库与公开内容，依用户明确授权执行；没有上传就交付本地候选包，不能报告“已开源发布”。必要的署名与许可信息随包提供。
