# 内容推进动画

每个分镜是一个可理解的解释单元。动画使观众看见新增信息、状态变化或关系形成，不能只有标题入场之后长时间静止。

## 可组合的镜头方法

| 内容 | 镜头内部推进 | 准确性与可读性 |
|---|---|---|
| 产品界面与功能 | 先完整显示界面；口播到功能时强调真实控件，旁边出现提炼文字；最后汇总 | 不改写静态截图内容；描边不盖文字，不暗示真实点击发生 |
| 多路接入、统一调用 | 来源逐个建立 → 接入关系绘制 → 公共层强调 → 应用端接收 | 先确认关系依据；光点表示解释示意，不表示实测时延或并发 |
| 架构或适配范围 | 按叙述建立层次 → 层内类别逐个呈现 → 解释已知职责 → 连接已证实层间关系 | 层次是讲解组织，不能凭空补内部实现；不要把类别清单画成强制串行流程 |
| 确有先后关系的任务流程 | 输入 → 处理 → 输出，当前步骤高亮，已有结果保留 | 没有真实界面录像时，使用清楚的示意卡片，不伪造产品操作 |
| 多应用由平台支撑 | 单个应用完整读图 → 画面缩小归位 → 多应用组成应用层 → 平台建立支撑关系 | 缩小后仅用来认出应用，细字阅读在缩小前完成 |
| 产品结果或对比 | 展示有来源的前后状态或数据 → 标出变化 → 收束价值 | 没有数据不做计数器、百分比、性能对比；不把规划效果画成已验证结果 |

## 单镜计划

每镜至少记录：

- 覆盖的口播与事实编号、起止时间。
- 真实素材及画面分区，标题/截图/关系/字幕的空间。
- 各内容事件的时间、对应语句、改变对象、观众此刻应理解什么。
- 阅读稳定区间；进入、归位、退出如何承接下一段。

事件随语义和真实语音安排，无统一最低数量。一个短镜头可能只有一个关键状态变化；复杂关系可能需要更多。文字出现、淡入或平移只有在显露新信息时才算内容事件。给所有卡片同样滑入，仍可能是静态幻灯片。

## 时间与镜头

常用入场可从0.3–0.8秒起调；复杂布局重组适当放慢。截图完整阅读通常至少需要数秒，但密度、分辨率和受众不同，应看渲染结果决定。不要一律套固定时长。阅读时不持续旋转、缩放、透视或漂移截图。

标题和解释保持清楚的前后关系，关系线走空白区；屏幕安全边距和字幕空间按输出尺寸设计。移动前后都核对落点，不能只看初始 CSS。

若采用 GSAP，初始化状态放入样式，动画按时间可确定地 seek，局部运动与镜头层分离，避免父子透明度互相影响。使用本地字体并在新增文案后更新子集。使用 HyperFrames 时依当前版本的组合与媒体时序规则制作，不照搬旧版绝对路径或写死 CLI 版本。

## 代表分镜验收

先选能证明这套方法的完整段落：有产品材料、有随讲述发生的内容变化、有完整结论。交付可播放的整段，说明重点秒点。用户确认后锁定该段再扩展，不能用另一套简单样式替换已确认效果。
